# decisionの起動コスト削減とGlow表示への移行

記録日: 2026-10-09

状態: 実装・全体テスト・実Glowでの端末確認・コードレビュー完了。

## 目的と方針

利用者はshellから `henji decision` を繰り返し起動する際の処理コスト削減を希望した。
初回計測では約22msを要し、decisionで使わないMarkdown表示関連ライブラリの初期化が大きかった。
外部ライブラリの上流改修や実行ファイルの分割を前提にせず、Henji本体を1バイナリに保つ。

利用者の合意により、内蔵Markdown表示を外部Glowの任意利用へ置き換え、質問JSONの重複検証と
共通初期化の冗長な処理を整理した。有料APIはこの改善の検証では呼び出していない。

## 変更した動作

- `glamour`、Chromaと不要になったMarkdown関連の依存を削除した。
- 通常のTTYテキスト表示のみ、生成完了後に `PATH` 上の `glow` を実行する。
- Glowにstdinで全文を渡し、整形結果を受け取ってから表示する。途中出力後にGlowが失敗しても、
  途中の整形結果と原文を重複表示しない。未導入・失敗時は元のMarkdownを表示する。
- `GLAMOUR_STYLE` をGlowの `-s` に渡し、未指定時は `auto` を明示指定する。
  `word-wrap` を `-w` に渡す。Glow側のページャ・TUIは子プロセスの環境変数で無効にする。
- Glowの診断はstderrへ追加しない。取消時はGlowを停止してエラー終了し、原文を追加表示しない。
- `--raw`・パイプの断片ごとの逐次出力を維持する。JSON・JSON Schema・decisionはGlowを使わない。
- 質問JSONは `ParseQuestions` で一度検証し、所有するコピーとプロトコルを非公開にした
  `Questions` 型で通信処理へ渡す。通信処理は未設定値とプロトコル不一致を拒否する。
  CLIでは引き続き認証・stdin読込みより先に質問ファイルを検証する。
- フラグの説明文は登録時には装飾せず、help表示時に装飾する。設定ディレクトリの作成は
  設定ファイルがない場合だけ行う。既存ファイルの所有者・権限確認を維持する。

初回確認時、この環境の通常PATHにはGlowがなかったため、検証用v3.0.0を
`/tmp/henji-glow-validation/glow` に配置した。その後、利用者の依頼に従い、確認時点の最新版
v3.0.0を `/usr/local/bin/glow` へグローバルインストールし、バージョン・stdin整形を確認した。
GlowをHenjiのGo依存として追加したり、同梱したりはしていない。

## 比較計測

Go 1.27.1、Linux amd64、同じ通常の `go build` オプションで変更前後のバイナリを比較した。
短い架空の文章・2問をローカルHTTPの即時応答APIへ送信し、起動から終了までを計測した。
設定は同じ2,682 bytes・5 API・14モデル相当の構成で、実キーを使わず環境変数でダミーキーを渡した。
前後・両プロトコルを交互に各120回実行した。プロセス起動・CLI処理・ローカル通信を含み、
外部APIの処理時間・DNS・TLSは含まない。このVMでの温まった状態の観測である。

| プロトコル | 変更前中央値 | 変更後中央値 | 変更前p95 | 変更後p95 |
| --- | ---: | ---: | ---: | ---: |
| OpenRouter | 22.969ms | 8.866ms | 30.006ms | 14.206ms |
| OpenAI | 22.990ms | 9.126ms | 29.295ms | 12.742ms |

中央値で約60〜61%短縮した。バイナリは87,271,382 bytesから79,909,073 bytesへ縮小した。
APIの応答時間やHTTPS接続確立のコストは残り、プロセス間でHTTP接続を再利用する機能は追加していない。
JSON Schemaの初期化も残る。

計測時の生データは `/tmp/henji-decision-perf-i1o72fuw/` にある一時資料で、継続保存は保証しない。

## 検証

- `go test ./...`、`go vet ./...`、`go build` が成功した。
- Glowの成功・未導入・途中出力後の失敗・実行中の取消を子プロセステストで確認した。
- raw・パイプでは生成完了前に最初の断片を読み取れることを確認した。
- JSON Schema・JSON出力・decisionの経路と既存Hayari／Shirushi向けのCLIテストが成功した。
- 実Glow v3.0.0を使ったPTY確認で、通常表示は整形され、未導入・失敗時は原文を表示し、
  rawはANSIなしで直接出力した。各ケースexit 0・stderrなしを確認した。
  Glow側に `pager: true`・`tui: true` があっても表示時には無効になることを確認した。
- 独立したコードレビューで必須指摘は残っていない。
- race検査は、この環境にCコンパイラがないため未実施。実プロバイダへの追加要求も行っていない。
